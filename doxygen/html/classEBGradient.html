Detailed Description

Class for computing gradients in an EBAMR context.

Although computing the gradient might seem like an easy thing to do, the presence of a coarse-fine boundary together with an EB complicates both the stencil availability and the consistent handling of the gradient on the coarse level. This class introduces a two-level view of such stencil computations. This class uses regular second order finite differencing in regular regions, including those covered by a finer level. Near the EB, however, the stencil might reach into cut-cells that are covered by the finer level. The invalid data might be filled with bogus data, or at the very best coarsened from the fine level. Since there is no consistent way of doing that coarsening (both conserative and averaging make sense), this class switches to a least squares based approach for such cases. In those particular corner cases we only reach into valid regions in the domain. Because of that, the directional derivatives in those cells are in the form 

 d(phi)/dx = sum(vofCoar) w(vofCoar)*phi(vofCoar) + sum(vofFine)[w(vofFine)*phi(vofFine)]

i.e., the gradient is a two-level stencil.

In cut cells and next to the domain boundary, the derivative in a direction is a centered difference if the cells on both sides are available, and otherwise a second order one-sided difference that reaches two cells away. Only if the second cell is not available does the stencil drop to a first order one-sided difference. Near the refinement boundary these stencils only use valid cells, i.e. cells that are not covered by the finer level. If that costs order, the cell gets a two-level least squares stencil instead, fitted to the valid coarse cells within the reach of the finite difference stencils and to the fine cells under the covered ones.

Note
This class requires at least one ghost cell. The second order one-sided differences require two ghost cells, both in the data and in the EBISLayout; with fewer, the one-sided differences are first order.
The second order one-sided differences are only as accurate as the data near the EB. With a first order EB boundary condition in the solver that produced the data (e.g. FieldSolverGMG with gmg_bc_order = 1), they can amplify its error; second order boundary conditions give the most accurate gradients.

Compute the gradient component which is normal to the face, using centered differencing.

If the face is oriented along dir, this computes the dir-component of the gradient using centered differences on the face. This routine is useful after e.g. averaging a cell-centered gradient to faces (in order to shrink the stencil).

Get the finite difference stencil for the gradient in a cell, assuming that the data is cell-centered.

In each direction this is a centered difference if the cells on both sides are available. Otherwise it is a one-sided difference, second order if m_stencilWidth is two and the second cell is available, and first order if not. Cells in a_invalidCells are treated as unavailable.

Parameters
[out]a_stencilFinite difference stencil. Component dir holds the derivative in direction dir.
[in]a_vofGrid cell
[in]a_ebisBoxEBISBox
[in]a_invalidCellsCells that the stencil may not use. If nullptr, all cells can be used.
Returns
True if leaving out a_invalidCells did not lower the order of the derivative in any direction, and every direction has a stencil. Always true when a_invalidCells is null.

Check if the level finite difference stencils in a cell only reach into valid cells.

This will check the stencils for all vofs in a_ivCoar. Stencils in cut cells may not reach into any covered cell. Stencils in regular cells may reach into covered regular cells, whose data is the average of the finer cells, but not into covered cut cells.
