Detailed Description

Declaration of a distributed, MPI-safe nearest-neighbor particle-merge algorithm.

This file adds a nearest-neighbor super-particle merge that is safe across patch and rank boundaries. Candidates are found against a particle's full neighborhood (its own patch plus every ghost, filled once per round); a pair where neither participant is reachable from outside the patch resolves immediately (the "trivial tier"), and everything else goes through a propose/judge/verdict protocol that is safe for any number of simultaneous cross-patch suitors.

Author
Robert Marskar

Build a patch's spatial index for one round: an EBGeometry SIMD PointCloudBVH over the whole patch (every local valid particle then every ghost) plus its precomputed k-nearest- neighbor graph – UNLESS no cell in this patch could possibly be crowded, in which case nothing is built.

The point cloud carries each point's globalID as metadata; a hit's cloud index decodes ownership (c < nLocal => local valid, else ghost). After the cloud is built, its whole a_kNearest-nearest-neighbor graph is precomputed once via PointCloudBVH::allNearestNeighbors() (batched, leaf-order/cache-warm, own-leaf-seeded) into a_index.pointCloudGraph and reused across every internal a_iterateLocalTierToConvergence pass (positions never change within a round; only consumed status does, and that is filtered at lookup time – see findNearestNeighborCandidates()).

Per-cell pre-filter: if NO cell in this patch has more than a_numParticlesPerCellThresh particles, nothing is built (a_index.pointCloud stays null, exactly as if the patch had zero particles) – the SAME cheap "is this even worth it" check equal_weight_kd effectively gets for free by dispatching per cell. This is an EXACT check (not an average-density heuristic, which would be a real bug: a low-average patch can still hold one badly-clustered over-threshold cell): a lightweight per-cell tally of the patch's own particles, keyed exactly as the crowding trigger (cellKeyOf(pos, probLo, dx), local and ghost alike), decides it directly.

For every over-threshold, currently-alive valid particle in a patch, find its single TRUE nearest neighbor among {this patch's own other valid particles} union {every ghost shipped to this patch}.

This is the only place a nearest-neighbor search happens, and it always runs against the full (local + ghost) view, never a local-only view: restricting it biases boundary-adjacent particles toward worse matches than interior ones. Crowding eligibility (is the query's own cell over threshold) is checked here at generation time from the live per-cell counts over valid + ghost occupancy; the symmetric check on the candidate's cell is done later, dynamically, by resolveTrivialTier()/judgeProposals(), since earlier merges this round can change it.

a_localValid/a_ghosts are this patch's full, unfiltered sets for the round; this function does the alive-filtering itself via a_consumedIDs (checked against both the query and every candidate). a_spatialIndex is built once per patch per mergeNearestNeighborsRound() call over the full set and reused across every a_iterateLocalTierToConvergence pass via this same lazy-deletion check, so it is never rebuilt per pass.

Each query's precomputed row is read from a_spatialIndex's k-nearest-neighbor graph (see NNSpatialIndex::pointCloudGraph / buildNNSpatialIndex()), computed once for the whole patch via the EBGeometry SIMD PointCloudBVH's batched allNearestNeighbors(). Per-query work is a row lookup plus filtering: a hit is skipped if its id is in a_consumedIDs, or (when a_maxCellDistance is set) if it lies beyond the bound; survivors feed the shared top-K logic that builds the edge. Self is excluded by the graph (each row is the nearest OTHER points).

a_maxCellDistance, when set, filters the graph row: rows are distance-sorted, so an out-of-bound candidate is farther than the bound and can never displace a within-bound one, and filtering yields exactly the within-bound k-nearest (see its param docs for the exact, safe-but-not-tight bound).

When a_maxFallbackCandidates > 0, the graph is built with k = 1 + a_maxFallbackCandidates, so each row holds the K nearest and NNMergeEdge::fallbackCandidates is populated with candidates 2..K (distance-sorted); resolveTrivialTier() walks that pre-fetched list when the primary is blocked, without re-querying the index.

Package one outgoing proposal for every edge that resolveTrivialTier() could not resolve locally, bucketed by destination rank.

Routing rule: ALWAYS to the owner of the candidate (NNMergeEdge::candidateID's owning rank) – never by any id comparison (see NNMergeProposal). If the destination rank equals this rank's own (a boundary-exposed candidate that happens to live in a DIFFERENT patch owned by the same rank), the proposal still goes into the normal per-destination-rank bucket – the caller (mergeNearestNeighborsRound()) is expected to hand the "bucket addressed to myself" directly to judgeProposals() in-process, without an actual MPI round-trip, while every other bucket goes out over MPI. This keeps the decision logic in judgeProposals() completely unaware of whether a given proposal arrived locally or over the network – it still goes through the exact same pooled judge logic, never a shortcut.

Judge every incoming proposal that targets a particle this rank owns, and produce the verdicts to send back.

The full rule set this function implements, summarized:

  1. Group incoming proposals by target id.
  2. For a target with NO outgoing commitment of its own: the eligible candidate is the minimum-distance incoming proposal (deterministic id tiebreak on exact ties).
  3. For a target that DOES have its own outgoing commitment (i.e. it is simultaneously proposing to something else): normally reject every incoming proposal unconditionally (it is "spoken for") – EXCEPT when its own outgoing target is itself one of its current incoming proposers, a genuinely mutual best-match pair. Blindly rejecting that case causes a PERMANENT deadlock (a stable mutual pair proposes to each other identically every round and is rejected every round, forever, since nothing changes to break the symmetry) – so it must be accepted instead. Because BOTH sides of a mutual pair detect the match independently, a deterministic tiebreak (lower-id side performs the accept, higher-id side falls back to the normal reject) is required, or both sides would accept and double-merge the same two particles.
  4. ALL eligible target decisions (plain-argmin and mutual-match alike) are resolved in ONE globally distance-sorted pass across every target this rank is judging (with an id tiebreak) – NOT by iterating targets in whatever order the incoming-proposal list happens to be in. Accepting one target decrements its cell's live count, which can push a DIFFERENT target sharing that cell below threshold; judging targets in arbitrary order makes that outcome depend on arbitrary processing order. Sorting closest-first with a dynamic per-target threshold recheck (mirroring resolveTrivialTier()'s discipline exactly) removes that dependency.
  5. This handles any number of simultaneous suitors for one particle, not just pairwise boundaries – a corner where 3+ patches meet is resolved by this exact same logic, with no special-casing, since every proposal naming a given target funnels into the same "group by target id" step regardless of how many different ranks it came from.
  6. A_maxCellDistance and a_isPositionValid apply here exactly as they do in resolveTrivialTier() – a physical-validity rule, not a coordination one. An incoming proposal that is too far, or whose weighted-centroid position fails a_isPositionValid, is never eligible to be accepted (skipped as though it did not exist for argmin purposes), REGARDLESS of the mutual-match exception in rule 3 – an invalid position is invalid on both sides of a pair, mutual match or not.

Proposals addressed to this rank's own particles arrive from two sources, pooled identically here: proposals received over MPI from other ranks, and this rank's own generateProposals()-produced bucket addressed to itself (an in-process handoff, no network round-trip – see generateProposals()).

Resolve every candidate edge that is safely mergeable with zero cross-rank coordination, and mark which remaining particles have committed to a non-trivial outgoing proposal.

An edge is trivial-tier eligible iff NEITHER the query nor the candidate is boundary-exposed (see isBoundaryExposed()) – this check happens AFTER finding the true nearest neighbor, never as a restriction on the search itself.

All eligible edges (across every patch this rank owns) are processed in ONE globally distance-sorted order, with a deterministic secondary tiebreak on participant ids – exact distance ties (e.g. true mutual nearest neighbors) are common enough that leaving them to arbitrary iteration/insertion order produces real, observed nondeterminism that cascades into unrelated pairs several hops away.

At the moment each edge is actually processed (not at generation time): re-verify both participants are still alive (lazy invalidation – skip if either was already consumed by a closer edge processed earlier in this same pass); if the candidate is local, re-verify it has NOT, in the meantime, committed to its OWN outgoing (non-trivial) proposal – a purely geometric "exposed" check on the candidate alone is insufficient, since a non-exposed particle's true nearest neighbor can still be a foreign ghost even though the particle itself is unreachable externally; consuming such a candidate trivially anyway is a real double-consumption bug this dynamic recheck closes. Finally, re-verify both participants' CURRENT cell occupancy (reflecting decrements from edges already processed this pass, not the generation-time snapshot) still exceeds the threshold.

On a successful trivial-tier commit: remove both participants from the caller's own valid particle list (conceptually – see a_consumedIDs), decrement both cells' live counts, and record the merge via a_combine/into a_results. On an edge that cannot be resolved trivially, exactly one of two things happens, and the distinction matters:

  • If the candidate is a ghost, OR either participant is boundary-exposed, OR the candidate turned out to already have its own outgoing commitment: mark the query particle as having an outgoing commitment (see a_hasOutgoingCommitment) so generateProposals() can pick it up. In all three cases the candidate genuinely still exists (it just isn't trivially available right now), so a proposal is meaningful – judgeProposals() already has a rule for "target has its own outgoing commitment" (accept only on a mutual match, reject otherwise), and that rule is exactly what should get a chance to run here, not a silent no-op.
  • If the candidate is stale (already consumed – found dead by the lazy-invalidation check above): do NOT mark the query particle as having an outgoing commitment, and do NOT generate a proposal. There is no meaningful id to propose to. Critically, this also means the query particle is NOT marked "busy" – it remains fully available for some OTHER particle to claim as an ordinary trivial candidate later in this same sorted pass, or via a_maxFallbackCandidates below.
