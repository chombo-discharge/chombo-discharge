Detailed Description

template<typename T>
class Scratch< T >

Single owner of a temporary that belongs to a ScratchPool.

A Scratch is obtained from AmrMesh::fetchScratch (or ScratchPool::acquire) and returns the temporary to its pool when it is destroyed. It can be moved but not copied, so a temporary has exactly one owner at a time. It has no default constructor and cannot be assigned. It must never be stored in a class member (the compiler does not prevent it, e.g. through a constructor's initializer list or std::optional): the entry would stay in use for the object's lifetime, and the pool aborts at the next regrid. Data that must live longer than the function that fetches it is fetched by a caller that spans all of its uses, and passed down by reference.

The handle converts implicitly to T&, so it can be passed directly to non-template functions that take the data by reference. A function template that deduces the data type from its argument (e.g. AmrMesh::copyData or the templated DataOps functions) does not see the conversion, and takes handle. References and aliases (e.g. Vector<LevelData<T>>) taken from it are views: they must not outlive the handle. Copying the underlying EBAMRData into an object that outlives the handle is an error. The pool detects shallow copies of the EBAMRData levels when the handle is destroyed. It cannot detect aliases built with AmrMesh::alias, EBAMRData::slice or aliasLevelData, so those must never outlive the handle either.

The data is uninitialized when fetched. It has exactly the number of components and ghost cells that were asked for.

Template Parameters
TData type. One of the types ScratchPool stores.
